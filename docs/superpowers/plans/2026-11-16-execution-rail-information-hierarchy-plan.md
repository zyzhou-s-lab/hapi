# 执行轨道信息层级改动方案

- 日期：2026-11-16
- 状态：已实施；首轮隔离验证后，根据真实会话反馈修正错误成员汇总及任务标题层级，并在原会话完成追加验收。
- 目标：把执行轨道从“工具调用清单”改成“可阅读的工作过程”。
- 参考：用户提供的 T3 Code 截图；HAPI 当前轨道渲染和合并规则。截图仅作为展示参考，不代表已核实 T3 的内部实现。

## 1. 改动目标与范围

展开整轮后，直接看见过程说明、操作汇总、子任务进展和重要事件；原始输入输出继续按需展开。

沿用现有视觉风格、工具预览和交互组件，不重做整套聊天 UI，不引入模型生成摘要。

限定在前端展示投影和轨道组件，不改 CLI、hub、数据库或传输协议。既有子任务字段链已核实，证据和缺字段处理见第 5 节。

## 2. 目标展示层级

整轮仍保留一个总开关，展开后按原始时间顺序展示：

| 内容 | 第一层直接显示 | 继续展开 |
|---|---|---|
| 过程说明 | 原文 Markdown | 无需额外折叠 |
| 连续常规操作 | “运行 3 条命令、读取 7 个文件、修改 2 个文件” | 原子工具列表，再查看各自输入输出 |
| 单次常规操作 | 有意义的操作摘要，如命令、文件名或搜索目标 | 工具输入输出；不额外套操作组 |
| 子任务 | 名称、真实状态、结果片段、可用的耗时信息 | 完整任务内容／子会话入口 |
| reasoning | 思考折叠入口；不冒充面向用户的说明 | 思考正文 |
| 权限、提问、未恢复错误 | 直接显示交互或错误信息 | 技术细节 |
| 上下文压缩等系统事件 | 独立事件行 | 可用的详情 |
| 最终回答 | 继续位于执行轨道外 | 保持现状 |

不增加折叠层数。新操作组取代普通模式的同类工具组，不能形成“操作组 → 同类组 → 工具 → 详情”。

## 3. 分组规则

### 3.1 常规操作：按连续过程分段，允许混合类型

新增展示概念 `ActivitySegment`，复用现有动作计数逻辑：

- 连续的读取、搜索、命令、修改等常规工具，可以进入同一段。
- 正文、reasoning、子任务、Todo、压缩事件、权限／提问等特殊工具截断常规段。段内后续出现错误或权限时仅显露对应成员；其余可安全隐藏的成功项继续汇总，不拆段搬动后续 DOM。
- 两个及以上可安全隐藏的成功调用显示混合计数摘要；单个调用直接显示工具摘要。运行、排队、已展开或持有焦点的调用不被汇总隐藏。
- 分组只改变展示，不修改源消息，不重排事件。
- 无法识别类别的工具保留名称和数量，不能静默忽略。
- reasoning 保留独立入口；`thinking` 保留原有同类分组，`verbose` 保留原子调用，不与普通模式混合段叠套。

展开操作组后直接列出原子调用，复用现有 `StepInlinePreviewCard` 查看详情。

### 3.2 工具摘要：完成后仍要说明“操作了什么”

当前部分工具完成后会清空 `intentLabel`。调整为：

- 读取保留文件名，搜索保留目标／模式。
- 命令保留命令或已有描述。
- 修改保留文件目标。
- 通用工具至少保留名称和已有意图。

状态从“正在运行”变成“已完成”，不应同时把可识别目标也抹掉。

### 3.3 子任务：作为任务呈现，不作为普通工具计数吞掉

- 按真实任务标识关联派发、进度和完成事件；不靠相同名称合并。
- 同一任务更新同一张卡片，并行任务分别展示。
- 原生任务优先以显式 `input.agent` 作为标题，`summary`／`description` 仅作缺失时的回退，不让完整派发指令取代任务身份；标题与 ID 相同时不重复显示，原始指令仍在详情。
- 结果片段来自已有结果文本，不另调模型总结。
- 派发工具调用完成，不等于子任务完成。
- 子任务相关的等待、通知调用保留在详情中，不反复生成相同任务卡片。

## 4. 流式更新与状态约束

以下约束与展示规则一起实现：

- 只增长当前尾段：遇到分段边界后，之前的段不再被重新拼组。
- 段的 key 基于首个稳定事件标识，不使用数组位置或当前计数。
- 当前运行的动作在第一层可见，不能藏进“已完成若干操作”。
- 动作完成后原位更新计数；错误、权限请求原位显露，不排序到时间线顶部。
- 新消息到来、组件重挂载及模式切换不意外重置已有展开状态。
- 沿用整轮完成后的收起规则，不顺带改变默认开合体验。
- 保留 Todo、问答、权限、最终回答及分享捕获路径，避免正文重复或缺失。

## 5. 文件级改动与数据边界

以下路径均位于 `web/src/components/AssistantChat/messages/`：

| 文件 | 计划改动 |
|---|---|
| `turnBlockModel.ts` | 增加操作段投影及混合摘要；普通模式不再叠加现有同类合并；明确分段边界和稳定标识 |
| `TurnExecutionRail.tsx` | 按时间顺序渲染正文、操作段、子任务及重要事件；保留运行前沿和原有交互 |
| `TimelineStepRows.tsx` | 复用原子工具行／预览；补足完成态摘要；剥离普通模式不再需要的嵌套分组路径 |
| 新增 `ActivitySegmentRow.tsx` | 只负责混合操作摘要、展开原子调用列表，不再做第二套分类 |
| 新增 `SubagentActivityRow.tsx`、`subagentActivity.ts` | 按真实任务 ID 投影任务卡片；复用原工具预览追溯，不虚构独立会话路由 |
| `TimelineTurnBlock.tsx` | 仅在需要传递投影或展开状态时调整，保留现有 slots 和最终回答布局 |
| 对应模型、交互测试 | 更新受影响的行为契约，覆盖分段、流式更新和异常可见性 |
| 相关功能文档／changelog | 记录普通模式的新展示规则及详细模式差异 |

已核实既有 `agent-run-*` 事件经 reducer 形成 `CodexAgent` 工具块，携带真实 agent ID、状态、父调用关联及结果；离线测试覆盖事件 → reducer → partition → 任务投影。任务终态和耗时取自 lifecycle，不借派发／等待工具的完成态或耗时。未知身份不生成任务卡；无本轮 lifecycle 不吞掉原工具；只有派发回执时不误报完成。追加真实会话展示验收见第 8 节。

其余默认不动 CLI、hub、持久化格式和传输协议。

## 6. 实施顺序

1. 确定投影契约：操作段边界、任务关联、各模式的展示差异。
2. 替换普通模式分组：先完成混合操作摘要及原子详情，撤出旧的叠套分组路径。
3. 接入任务卡片和重要事件：保持源事件顺序及真实状态。
4. 打通流式与展开状态：处理运行、完成、失败、权限暂停和恢复。
5. 浏览器验收后收尾：删除被替代的普通模式死路径，更新文档。

`thinking`、`verbose` 继续保留查看思考／完整调用的用途，不新增一个“类似 T3 模式”的设置。

## 7. 验收清单

### 7.1 展示结果

- 展开整轮即可读懂过程，不必逐个打开工具才能理解在做什么。
- 混合的命令、读取、修改能汇成一行；正文和子任务不会被吞入汇总。
- 单次工具不增加无意义的包装层。
- 子任务名称、真实状态及可用结果片段直接可见。
- 最终回答只出现一次，原始工具输入输出仍可追溯。

### 7.2 状态与交互

- 流式追加不会导致旧段跳动、重复、丢失或折叠状态复位。
- 并行任务、延迟返回、失败任务不会串卡或误报完成。
- 权限、提问、错误在第一层可发现并可操作。
- 刷新、模式切换、分享捕获后没有内容遗漏。

### 7.3 验证方式

- 模型测试验证分段边界、顺序、计数和事件归属。
- 组件测试验证展开状态、权限交互和流式转换。
- 实际浏览器验证视觉层级：普通／详细模式、运行中／已完成、桌面／窄屏，以及长路径、长结果和中英文内容。测试通过不能代替这一项。
